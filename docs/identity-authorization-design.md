# 身份与授权

OPS 是统一身份来源。账号通过多角色关联权限；当前预置 ADMIN、OPS、VIEWER 角色，可在用户管理页面配置角色权限、账号状态、密码和 AI 可访问的站点。业务端以权限点校验，不依赖页面隐藏按钮。所有角色、权限和站点授权的更新会增加账号授权版本，已登录会话在下一次请求失效。用户和角色更新写入运营审计日志。

AI 使用 OPS 的会话与稳定用户 ID，不缓存会话身份；AI 自身的 Agent、工具和环境策略仍与用户权限共同生效。Run 保存创建时的授权版本，排队执行、工具调用和事件流重新核验身份，授权发生变化后拒绝继续。AI 查询运营数据时，OPS 使用服务身份获取真实用户并重新检查账号状态和用户站点范围，再与 AI 策略范围取交集。

站点限制目前只对 AI 业务查询实现细粒度控制。运营端尚未对设备、订单、汇总等所有查询实现站点行级过滤，因此站点受限账号的运营数据接口一律拒绝，不能将此限制当作运营端的完整多租户实现。后续要开放受限账号的运营页面，需先在列表、聚合、详情和写操作中统一实施服务端数据范围过滤并增加越权测试。

首次运行时 Flyway 在 OPS 执行 V9，将原有单角色数据迁入多角色表；AI 执行 V5，为 Run 增加授权版本。AI 会话及历史 Run 的归属由用户名改为用户 ID；旧演示会话不会自动迁移，旧排队任务不能继续执行。请同时重启 OPS、AI 和前端；运行账号需要对应 schema 的迁移权限。
