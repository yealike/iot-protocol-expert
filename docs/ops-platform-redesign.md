# 充电运营平台重新规划设计

> 状态：设计方案，尚未实施。范围以当前充电桩业务为主，兼顾未来双向充放电；时间、金额和设备状态口径需在实施时与业务确认。

## 1. 现状与目标

当前系统由独立 React 前端、ops 运营服务、protocol 协议通道、simulator 模拟器和 codec 库组成。协议通道负责接入与转发，业务数据保存在 ops。当前总览只展示设备、站点和告警等基础数量，页面仍有与当前业务不符的「光储充放全类型设备」文案。

代码已有的基础能力：

- `device_instance.product_id` 非空并关联产品；设备新建页面已要求选择已发布产品。需要强化绑定规则、编辑体验和关联跳转，并非从零增加关联。
- 产品后端已有创建、更新、删除接口，写操作要求 ADMIN；前端产品页目前缺少完整操作入口。物模型以产品 `metadata` JSON 存储。
- `charge_order`、账单与费率模型已存在；后端已有订单列表、详情和账单查询接口，前端缺少订单页面。现有订单查询返回列表，需补充分页及稳定排序。
- 订单金额区分设备账单与平台估算；当前订单模型没有支付流水，也没有独立的充、放电方向和双向电量账本。不能把估算金额标为实收，也不能用零值伪装不支持的放电数据。

目标：让运营人员从总览发现问题、从设备详情定位问题、通过订单核对交易；让管理员维护产品和物模型，并确保设备与产品的关系可追溯。

## 2. 信息架构

```text
运营总览
设备管理
  设备列表 / 设备详情
产品中心
  产品列表 / 产品详情 / 物模型编辑
交易管理
  充电订单 / 订单详情 / 账单记录
告警中心
  告警列表 / 处理记录
协议文档
  文档列表 / 上传与下载 / 文档片段
基础配置（后续）
  站点 / 费率 / 用户与权限 / 操作审计
```

导航围绕日常运营任务组织；产品是设备的模板，设备属于产品与可选站点，设备下有多个枪口，订单关联设备和枪口。列表、详情、总览和告警均提供上下文跳转，保留筛选条件和返回位置。首页不使用演示数据填充真实指标。

## 3. 总览 Dashboard

顶部提供站点筛选、统计日期与刷新时间；默认全部站点、站点本地自然日，跨时区汇总统一明确展示所用时区。异常、加载、空数据和数据延迟分别展示。各指标支持点击跳转至带同样筛选条件的列表。

| 区域 | 设计 | 口径与数据来源 |
| --- | --- | --- |
| 核心指标 | 设备总数、正常、故障、离线、今日充电量、今日放电量、今日营收 | 设备状态见下文；电量按当天实际发生量；营收首期展示「今日已结算金额（含估算）」并分列来源，尚无支付流水时不称实收 |
| 运行态势 | 在线率、枪口状态分布、当前充电订单数、未关闭告警 | 设备和枪口状态、活跃订单、告警快照；注明刷新时间 |
| 业务趋势 | 今日按小时充放电量与金额，支持近 7/30 日切换 | 按实际增量及结算时间聚合；独立展示不同来源和未完成统计 |
| 待处理 | 最新严重告警、异常订单、离线设备 | 可按严重程度和时间排序并直达详情 |
| 站点表现 | 各站点设备数、在线率、充电量、已结算金额 | 站点过滤与上方一致，默认按异常或业务量排序 |

设备状态必须互斥并可核对：总数 = 未激活 + 离线 + 在线正常 + 故障；「正常设备」定义为在线且非故障。停用是独立维度，总数包含停用设备并单列停用数。离线且故障未解除时归入故障；在线率分母为已激活设备，零分母显示 `—`。具体投影规则见数据库设计。

每日充电量按可追溯的设备/枪口计量增量分配到发生时间，跨日订单按日切分；订单最终总量按结束日归集只适合「今日结算订单电量」，不能冒充当天实际电量。当前若缺少可靠采样、去重或跨日切分，显示「数据暂不可用」及原因；对缺测、回拨、补传做标识和重算。放电量需要协议明确上报放电方向和计量数据才启用，当前不支持时显示 `—` /「暂不支持」，与真实 0 区分。金额使用 decimal，按订单结算时间统计并标注币种、金额来源；退款和实收待支付域接入后分别核算。聚合返回统计区间、时区、更新时间、完整性/来源，避免前后端各算一套。

布局：第一行指标卡；第二行电量/金额趋势和设备状态；第三行告警与异常订单；底部站点表。桌面优先，窄屏卡片换行、图表与表格可横向滚动，不仅靠颜色区分状态。

## 4. 设备管理与详情

### 列表与绑定

列表支持设备编号/名称、产品、站点、协议、在线/故障/未激活、启停状态筛选；显示产品、站点、最近上报、枪口状态和待处理告警。新建设备先选择已发布产品，显示其设备类型、协议和物模型版本，再填写设备编号、协议设备编号、名称、站点与枪口；协议编号按协议唯一。编辑支持修改允许变更的档案、站点和枪口配置，不能静默更改协议身份。

产品是设备能力和协议的来源：创建时固化产品版本；已激活、存在订单或历史数据的设备默认禁止直接换绑产品。确需迁移时单独设计兼容性检查、停机、影响预览和审计流程，不能直接覆盖历史。未激活且无业务历史的设备可在校验后换绑。产品停用不删除既有设备；产品与设备关系有引用时禁止硬删除。

### 详情布局

- 顶栏：设备名称、编号、产品与版本、站点、在线/故障/启用状态、最近上报；操作按权限与状态展示，危险操作二次确认并记录结果。
- 运行概览：每个枪口独立卡片，展示状态、连接/充电情况、电压、电流、功率、SOC、当前订单、最近更新时间；缺失值显示 `—`，陈旧值标注。
- 实时与趋势：设备级和枪口级指标分组，支持属性、枪口、时间范围选择；时间序列必须带枪口维度，避免同名属性串线。
- 标签页：设备档案、运行数据、订单、告警/事件、指令记录、物模型。订单可跳到订单详情，告警和命令可定位处理记录；大列表服务端分页。
- 远程启停：只有协议支持、设备在线、枪口状态允许且操作者有权限时可发起；确认弹窗说明对象、动作与风险，展示提交、设备确认、超时/失败等真实状态，不能把「已提交」显示为执行成功。

## 5. 产品与物模型

### 产品生命周期

产品列表提供搜索、状态筛选、新建、编辑、复制和详情。创建支持从现有充电桩协议模板初始化，填写产品编码、名称、厂商、型号、设备类型、协议、传输方式、描述和默认配置。编码唯一；协议和设备类型按已实现能力约束，不提供会误导用户的任意组合。

建议生命周期：草稿 → 已发布 → 停用；已发布产品产生新草稿版本，编辑通过校验后发布，现有设备默认继续绑定原版本，不静默切换。停用后不能新建设备，历史仍可读。无设备、无历史引用的草稿可删除；其他产品只允许停用/归档。发布前展示新增、修改、删除及兼容性影响；同一产品和版本使用乐观锁防止覆盖其他人的修改。按角色控制新建/编辑/发布/停用/删除并记录审计。

### 物模型编辑器

产品详情分「基本信息」「物模型」「关联设备」「版本记录」。物模型按属性、功能、事件、标签分别列表，支持新增、编辑、删除和搜索。表单按类型呈现单位、范围、精度、枚举、对象/数组结构、说明；属性支持设备级/枪口级与读写权限；功能配置输入输出与同步方式；事件配置级别和载荷。标识在各类作用域内唯一且稳定，类型、范围、嵌套层级、枚举值由前后端共同校验；保留 JSON 预览/导入导出并经过同样校验。

已发布版本不可原地破坏：删除属性、修改标识/类型/单位/通道范围视作不兼容变更，需新版本及迁移方案；仅新增兼容项仍先预览并发布。模型声明不等于协议驱动已实现：对不可映射的功能标注「未实现」，禁止下发。设备覆盖 `derive_metadata` 需明确规则，首期默认只读展示有效模型及来源，避免产品版本与设备覆盖冲突。

## 6. 订单与账单

订单列表提供订单号、设备/枪口、站点、协议、状态、创建/开始/结束时间筛选，展示订单号、设备及枪口、状态、开始/结束、时长、电量、金额、金额来源。重建设计暂采用 `PENDING / CHARGING / STOPPED / SETTLED / FAILED`，分别展示待启动、充电中、已停止、已结算、失败；空时间和异常原因如实展示。支持稳定排序、服务端分页和条件重置。订单详情展示基础信息、状态变化、计量、电价/金额来源、关联账单、关联设备与指令/事件；未持久化的状态变化不编造，后续补充事件记录。

账单独立展示协议来源、来源交易号、接收时间、校验结果、金额/电量及关联订单；重复上报按协议交易唯一键幂等，原始报文与业务账单保留关联，异常账单可定位但不重复计入。设备账单和平台估算不可相加重复统计；补传或更正后记录版本与审计并触发聚合重算。支付、退款、发票和真实收入属于后续支付能力，不用当前订单状态代替支付状态。导出、人工补单、重算及远程停止列为后续受控操作，不作为首期默认功能。

## 7. 服务边界与数据设计

保持当前部署单元，优先在 ops 内按业务域分包，避免现阶段为了页面改造引入分布式复杂度：

| 模块 | 责任 |
| --- | --- |
| product | 产品、模型校验、版本与发布 |
| device | 设备档案、产品绑定、枪口、状态与实时属性 |
| telemetry | 属性上报、历史曲线、计量增量及数据质量 |
| charging | 订单状态机、账单、费率快照及幂等 |
| alarm | 规则、告警生命周期与处理 |
| protocol document | 协议文档元数据、项目内文件存储及诊断片段检索 |
| dashboard | 面向页面的聚合查询、统计口径与数据新鲜度 |
| access/audit | 认证授权、操作审计 |
| protocol adapter | ops 内部协议业务适配与统一领域事件转换 |

`protocol` 继续负责连接、编解码及协议翻译，`ops` 是设备、订单、账单的事实来源，`simulator` 只模拟设备行为。内部调用需明确超时、幂等键、失败重试和重复上报语义；持久化业务变化与聚合更新不能依赖一次无保障的内存事件。先基于数据库查询和可重算的聚合表实现，规模增长后再评估消息队列/独立分析服务。

数据库按个人 demo 从零重建，不迁移历史数据。采用独立 `ipe_ops` schema、无数据库外键；产品版本、计量、订单与账单等设计及应用层一致性约束详见 [数据库重建设计](ops-database-redesign.md)。新库初始化不自动清理已有数据库。

## 8. API 改造建议

- 沿用 `GET /api/ops/overview` 并版本化或兼容扩展，增加站点/日期/时区筛选及指标来源、更新时间、可用性；趋势可拆为独立查询以减少首页负载。
- 复用 `/api/ops/products` 现有 CRUD；补充模型草稿保存、校验、版本比较、发布、停用等接口，明确 400 校验、403 权限、404 不存在、409 引用/版本冲突。删除服务端必须校验引用。
- 复用 `/api/ops/devices`，设备写入校验产品发布状态、版本、协议和唯一性；详情增加当前订单和枪口数据，订单/事件/指令分别分页查询。
- 扩展 `GET /api/ops/orders` 支持分页、稳定排序及筛选；保留 `GET /api/ops/orders/{orderNo}` 与账单查询，增加来源和缺失信息，不改变现有协议内部接口语义。
- 新增 `/api/ops/protocol-documents` 列表、上传、详情、下载、归档和片段维护接口；按协议码、版本和标题筛选，操作权限与审计同产品管理。文件存储在项目空间，详见数据库设计。
- 写接口采用清晰 DTO、字段级错误、权限和审计；跨服务协议回调提供幂等与并发保护。兼容旧调用方后再移除旧响应结构。

## 9. 交付顺序与验收

1. **基础规则与订单**：统一设备状态、订单/账单口径；完成订单列表与详情、分页和设备跳转。验收：两种协议订单均可查询，空值与估算来源正确，重复账单不重复统计。
2. **产品及设备绑定**：完成产品 CRUD、草稿/发布、物模型表单校验、版本与绑定约束，设备创建/编辑流程。验收：无权限不可写；引用产品不可误删；不兼容变更不影响已绑定版本；协议编号冲突得到明确提示。
3. **设备详情**：重构档案、枪口、实时值、趋势、订单、告警和指令。验收：多枪同属性不串数据，离线/陈旧/无数据清楚，命令状态与设备实际响应一致。
4. **总览**：建立可信电量与金额聚合及数据质量展示，完成指标卡、趋势、异常入口。验收：跨日订单、补传、重复上报、计量回拨、无数据、时区边界、不同金额来源均有测试；指标与明细可核对；不支持放电时展示不可用。
5. **协议文档**：按协议码管理本地文件与诊断片段，支持权限、下载及文件与数据库一致性检查。验收：按协议版本可检索，重名文件不覆盖，缺失文件有明确提示，路径无法越界。
6. **增强**：站点与费率管理、支付与退款、受控导出、审计检索、数据修复工具；按实际业务需求迭代。

每阶段覆盖后端单元/集成测试、API 权限和迁移测试、前端构建与关键交互验证；从空库验证全新初始化、schema 隔离和重置流程。以上时间口径、正常设备定义、产品迁移策略和是否接入真实支付需与业务确认后定版。



订单充电过程时序存储与回放补充设计见 [充电过程时序与订单回放设计](ops-timeseries-design.md)。
